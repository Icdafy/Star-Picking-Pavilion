# 摘星阁（Star-Picking-Pavilion）

摘星阁是一款面向**低空经济**与**商业航天**两个行业的 Windows 桌面热点情报站。它在本机持续采集官方、媒体、交易所、一级市场媒体与公众号订阅等信源，用 AIHOT 式的精选链判断什么值得看，把同一件事的多家报道归成一个事件、按独立信源算热度，并把一级股权市场公司的融资、订单、试验与人事动态单独拎出来，每天、每周、每月出刊。

## v0.2.2 · 一级市场概览、交易所上市进程与免费信源扩容

- **一级市场「市场概览」**（默认分区）：融资事件数、涉及公司、亿元级以上、明确披露金额、领域分布五个指标，融资阶段（早期 / 成长期 / 后期 / 上市进程 / 战略与并购）、金额量级、月度节奏、热门赛道、大额融资、上市进程与活跃机构；点阶段直接跳到对应明细，点机构检索它参与的全部融资。
- **融资动态**：按阶段、事件性质、日期 / 金额量级 / 报道数筛选排序，一键导出 CSV（Excel 直接打开、防公式注入）或 Markdown。上市公司定增与可转债、融资租赁与债权、几方出资新设合资公司单独归类，不再混入一级市场统计、机构榜与刊期。
- **去重**：同一笔融资的全称、简称与母品牌写法（“广东高域科技有限公司”“高域科技”“广汽高域”）在 ±45 天内合并，“未披露”轮次由写明轮次的报道补全；历史重复记录升级时一次性合并，证据与投资方取并集。公司库新增 13 家近期有真实融资报道的两行业公司。
- **交易所上市进程（新 API 信源）**：上交所科创板与深交所创业板 / 主板的 IPO 审核项目动态（`sseipo://`、`szseipo://`），受理、问询、上市委、注册每一次状态变化生成一条资料，首轮即返回中科宇航、蓝箭航天、微纳星空、腾盾科创等在审项目。
- **免费信源扩容**：11 条带“资本守卫”（领域词库 + 标题资本信号，剔除融资租赁、两融）的一级市场检索线，投中网融资、泰伯网、无人机网，以及 TechCrunch Space、eVTOL Insights、Urban Air Mobility News、European Spaceflight、Via Satellite 五个海外 RSS。全部实测公开免费，详见 [信源实测](docs/v022-sources.md)。
- **热点更准**：同一批次各自开出的同一事件合并（星舰第 14 次试飞曾占 9 个热点中的 6 个）；东方财富转载文章按“文章来源”计真实出版方，不再把十几条检索线当成十几个独立信源。
- **AIHOT 同步**：移植上游 Atom XHTML 文本、无时区日期按信源时区、周报月报迟到资料归属，以及事件关系评测工具（`npm run eval:relations`）。详见 [AIHOT 整合审计](docs/aihot-integration-audit.md)。
- **信源监控台**：按名称 / 地址 / 说明搜索，按运行状态、类型、领域筛选，顶部显示运行中、异常与停用数量。

## v0.2.0 · AIHOT 内核重构：热点站 + 一级市场雷达

v0.2.0 以开源的 [AIHOT](https://github.com/KKKKhazix/AIHOT)（MIT）为底层逻辑，把摘星阁从“文章评分器”整体改造成“热点站”。改动覆盖采集、判断、归组、热度、出刊与界面，详见 [docs/intel-engine.md](docs/intel-engine.md)。

- **行业包 `config/industry/`**：站点与读者画像、8 种内容类型（政策监管、投融资与资本、发射与飞行、技术与产品、技术解读、订单与商业化、企业与产业动态、研究与观点）及其五轴权重、标签白名单、入选门槛、热度参数、公司库、全部提示词（Markdown）。改标准不改代码；提示词版本就是内容哈希。
- **精选链**：词库粗过滤 → 模型预筛（PASS / BLOCK / UNKNOWN，拿不准先补正文再判）→ **同一标准两次独立评分**（模型给内容类型与五轴 0–10，代码按类型权重合成 0–100）→ **两次之和 ≥ 2 × 信源门槛**才入选（官方一手 55、官方次级 59、媒体与聚合 63）→ 内容理解：自洽中文标题、答案先行摘要、面向投资人的推荐理由、主体公司、核心事实、原子事件、融资事件。
- **事件与热点**：报道增量归组为事件（字面 + 主事件键 + 主体公司召回，灰区交给模型判“同一件事 / 后续进展 / 两件事”），多来源事件自动生成综述。新增“**当前热点**”视图：48 小时内每个独立出版方只算一次、24 小时减半，至少 2 个独立信源才上榜，标注“爆 / 新 / 升 / 突破”，附小时热度走势。东方财富检索结果按原始媒体（财联社、证券时报……）计出版方，不再按检索线重复计数。
- **一级市场雷达**：新增“**一级市场**”视图——融资动态（轮次、金额、领投与参投、报道数，同一笔融资多篇报道合并）、公司热度榜、公司库（64 家两行业公司，含未上市标的与代表型号，可自建、可标记“关注 / 被投”）、公司档案（别名编辑、全部报道、融资记录）、活跃机构、“新发现公司”一键收录。标记关注或被投时自动为该公司新增检索线。
- **刊期**：日报之外新增**周报**（每周一 10:00）与**月报**（每月 1 日 10:30）；每期都有导语、热点事件、分类精选（同一事件只出现一次）、一级市场、“我的关注”、公司声量榜与技术突破。有密钥时导语由模型基于本期事实改写。
- **信源**：新增投资界（融资快讯、IPO 与退出、产业资讯）、创业邦，10 条一级市场检索线（低空经济 / eVTOL / 无人机 / 商业航天 / 火箭 / 卫星 × 融资、上市辅导、IPO），以及公司库中尚无检索线的 21 家未上市公司的检索线。公众号继续只走公开订阅（Wechat2RSS / RSSHub）与公开文章链接；搜狗微信搜索的 robots.txt 禁止抓取，因此不接入。
- **成本与可靠性**：每个付费调用先记回执，重试、重启、手动重跑直接复用已付费结果；每小时 / 每天调用预算熔断，超出后资料保持待分析。读者打开页面不会触发任何模型调用。
- **校准**：`npm run eval:selection -- --gold 样本.jsonl` 用你自己标注的样本跑预筛与两次评分，输出准确率、查准率、查全率与 40–90 分门槛扫描，判错条目逐条列出。
- **兼容**：数据库只做增量迁移，旧资料保留当时的评分与研判；v0.1.x 的事件簇原样升级为事件，历史资本市场资料按标题规则补抽融资事件，已判相关的资料按公司库补建主体关联。星标、日报、备忘、设置、凭据与界面偏好全部保留。

继续统一使用 `deepseek-v4-flash-vision-exp`。接口依据：[DeepSeek 图像理解](https://api-docs.deepseek.com/zh-cn/guides/vision/)与[首次调用 API](https://api-docs.deepseek.com/zh-cn/)。启用 AI 后，相关新闻正文及经筛选的图片会发送给配置的模型服务。

## 系统要求与安装

- Windows 10/11 x64
- 无需另行安装 Node.js、数据库或浏览器

从 [GitHub Releases](https://github.com/Icdafy/Star-Picking-Pavilion/releases) 下载 `Star-Picking-Pavilion-Setup-0.2.2.exe`，双击并按向导安装。v0.2.2 尚未进行代码签名，因此 Windows SmartScreen 可能显示“Windows 已保护你的电脑”；请先核对校验值，再选择“更多信息 → 仍要运行”。

下载 `SHA256SUMS.txt` 后，可以在 PowerShell 中验证安装包：

```powershell
Get-FileHash -Algorithm SHA256 .\Star-Picking-Pavilion-Setup-0.2.2.exe
Get-Content .\SHA256SUMS.txt
```

两处 SHA-256 必须完全一致。自动更新只从本项目的 GitHub Releases 检查；下载完成后，应用右上角会提示重启安装。

## 主要功能

- 精选、当前热点、一级市场、全部动态与星标五个情报视图
- AIHOT 式精选链：预筛、两次独立评分、分级门槛、自洽中文标题与答案先行摘要、面向投资人的推荐理由
- 事件归组与事件热度：独立信源计数、24 小时半衰期、爆 / 新 / 升 / 突破标记、小时热度走势与事件综述
- 一级市场雷达：融资事件抽取与合并、公司热度、公司库与公司档案、关注 / 被投标记、活跃机构、新发现公司
- 低空经济、商业航天领域和分类筛选；卡片上的主体公司一键直达公司档案
- 199 个内置信源：官方一手、央媒与科技媒体、交易所公告、一级市场媒体、关键词与公司检索线、公众号与外媒接入位
- 268 个词条的核心词库，带库内命中条数，点词即检索
- SQLite FTS5 全文检索（含中文标题、实体与主体公司）
- 日报、周报、月报，实时增量提示与可选的 08:00 自动保存研究归档
- 星标留存与「星标」视图，收藏的情报永久豁免数据保留清理
- 日报与信息流可复制为纯文本、导出为 Markdown，单条可复制标题与链接
- RSS、网页、公开 API 与 RSSHub 信源管理

## 捕捉什么、怎么打分

摘星阁只锁定两个领域：**低空经济**与**商业航天**。这两条线之外的内容，无论多热门，都会被判为无关。

### 核心词库

`config/lexicon.json` 定义了这两个领域的核心词：18 个分组、268 个词条、739 个匹配面，每条带权重（w=10 领域定义词，w=6~9 核心主题与具名主体，w=2~5 相关概念）与别名。它是一份事实、三处使用：

1. **检索入口**：点顶栏检索框旁的词库图标（或按 <kbd>Alt</kbd>+<kbd>K</kbd>）打开面板，按组罗列全部核心词，**每个词实时显示它在你本地情报库里的命中条数**，点一下就检索。可按领域筛选、只看有命中的词，或直接输入过滤。命中数与「全部动态」完全同口径，面板写几条点下去就是几条。
2. **粗过滤**：明显不沾两个行业的资料在词库这一步就被拦下，不花一次模型调用。
3. **采集与降级**：关键词型信源的入库守卫，以及未配置 API Key 时的启发式判定。

想加新赛道，改这一个文件即可；想加公司，改 `config/industry/companies.json` 或直接在「一级市场 → 公司库」里收录。

### 精选：两次独立评分 × 分级门槛

v0.2.0 起，精选标准写在 `config/industry/prompts/selection-score.md`，门槛写在 `config/industry/selection.json`。评分模型对每条资料**独立打两次分**：先判断内容类型，再给五个轴各打 0–10 的整数分——实质份量、信息增量、证据强度、共振面、投资可行动性——由代码按内容类型的权重合成 0–100（例如发射与飞行 3/2/2/2/1，投融资与资本 3/1/2/2/2，技术解读 1/3/2/2/2）。

```
入选 ⇔ 第一次评分 + 第二次评分 ≥ 2 × 门槛（按信源分级：T1 55 · T1.5 59 · T2 63）
卡片显示 = 两次平均（向下取整），悬停可见两次原始分与门槛
```

评分输入故意不带信源名称与等级，不让名气替事件加分；股评、涨停异动、泛泛表态、只有“拟 / 计划”的预告、多主题合集等噪声在评分标准里被显式压住。门槛只在你用自己标注的样本校准过后再改：`npm run eval:selection -- --gold 样本.jsonl`（格式见 `config/industry/gold.example.jsonl` 与 [docs/intel-engine.md](docs/intel-engine.md)）。改了门槛，已判过的资料按保存的两次评分立即重判，不重新调用模型。

技术突破不改变入选判定，只影响热度。它仅在低空经济、商业航天的允许分类中生效：标题或摘要必须在同一语句中同时出现明确技术对象和“完成、首飞、验证、交付、量产”等已实现动作，并通过 T1/T1.5 信源与模型可信度门槛；“计划、拟、或将、概念、传闻”以及营销噪声不会获得加成。卡片上的“技术突破”标识会说明命中的证据，规则集中在 `config/breakthroughs.json`，便于持续审计与迭代。

### 热点：按事件、按独立信源

同一件事，官网发一篇、媒体转十篇、公众号再写三篇，读者只需要看到一次。摘星阁把报道归成**事件**：用中文标题与摘要的字符相似度、主事件键（主体 · 动作类 · 客体）和主体公司召回最近 14 天的候选事件，明显相同的直接归入，灰区交给模型判断“同一件事 / 后续进展 / 两件事”，拿不准就不合并。发现时已发布超过 48 小时的旧文可以归入已有事件，但不开新事件、不计热度。

```
事件热度 = Σ 每个独立参与者 0.5 ^ (距其最近一次报道的小时数 / 24)     // 48 小时窗口
         × (1 + 0.25 × 技术突破强度)
上榜条件：至少 2 个独立参与者；与 6 小时前同口径比较，标注 爆 / 新 / 升
```

独立参与者按出版方计：东方财富检索结果使用原始媒体名，公众号使用账号名，其余使用信源。一家媒体发十篇只算一次。v0.1.x 的文章热度公式（质量分 × 半衰期）仍用于归档中的旧资料。

### 一级市场

内容理解会从融资、并购、上市辅导与 IPO 报道中抽出**融资事件**：公司、轮次（规范为种子轮 / 天使轮 / Pre-A 轮 … / 战略融资 / Pre-IPO / 上市辅导 / IPO / 并购）、原文金额写法（只换算明确的人民币数字）、全部投资方与领投方、日期和状态（已完成 / 已宣布 / 传闻）。同一公司同一轮次的多篇报道合并为一条，投资方取并集，状态只升不降；“完成新一轮融资”会挂到该公司 45 天内写明轮次的记录上。无密钥时按标题规则兜底抽取。

v0.2.2 起，融资事件另按性质分类（股权融资 / 上市进程 / 并购与转让 / 上市公司再融资 / 债权与租赁 / 合资设立），一级市场视图、机构榜与刊期默认只统计前三类；按轮次归入早期、成长期、后期、上市进程与战略并购，按原文金额写法归入千万以下、千万级、亿元级、十亿级以上（外币与约数只用于分档，不冒充精确金额）。库外公司的全称、简称与母品牌写法在 ±45 天内视为同一笔融资；公司库按“去掉地名、括号与行业后缀后的字号”唯一命中才自动归属。

公司库内置 78 家两行业公司的身份信息（名称、别名、代表型号、赛道、上市状态），不预置任何融资或估值数据。中文别名带词边界校验（“千亿航天”不会被认成“亿航”）。在「一级市场」里可以把任意公司标为**关注**或**被投**：被投公司的动态会进入每期刊物的“我的关注”，并自动新增一条专属检索线。

### 信源

信源分三级：T1 官方一手、T1.5 官方次级渠道、T2 媒体与聚合检索，等级决定入选门槛。v0.2.0 新增投资界（融资快讯、IPO 与退出、产业资讯）、创业邦资讯、10 条一级市场检索线与 21 条公司检索线。关键词检索线（`eastmoney://关键词`）默认相关性优先并叠加一路时效补充，可按 `?pages=2` 翻页；一级市场检索线用 `guard=capital` 同时要求领域相关与标题资本信号。公告与电报适配器还支持 `cninfo://`、`sse://`、`szse://`、`cls://`；v0.2.2 新增交易所 IPO 审核项目 `sseipo://[名称]?csrc=C37` 与 `szseipo://[名称]?industry=航空航天`。网页列表可用 `title`、`summary` 选择器从卡片式链接中只取标题与导语。标题与摘要都不沾关键词、也不落在同领域词库内的泛资讯会在入库前被丢弃；已知不可达或依赖登录态、自建服务的接入位默认停用。

微信公众号使用新增的「公众号安全采集」类型：可添加公开 mp.weixin.qq.com/s/ 文章链接，或填写公开 Wechat2RSS/RSSHub 订阅地址。订阅用于持续发现文章，直接链接仅跟踪该篇；不枚举账号、不借用登录 Cookie、不绕过验证码。每次最多读取 5 篇，公众号请求间隔 3 秒，遇验证/拒绝暂停一小时并叠加信源退避。正文遵守 robots.txt，过滤后只收低空经济和商业航天。内置公众号接入位需要自行配置可访问的订阅实例，默认停用，不能声称覆盖全部公众号。

## 留存与分发

情报看完之后有两条出路：留给自己，或者传给别人。

- **星标留存**：任意卡片右下角点「星标」即可收藏，「星标」视图按收藏时间倒序陈列，导航标签显示收藏总数。星标情报**永久豁免数据保留清理**，「待清理」计数也会排除它们；被判为无关、或身处事件簇中却不是主条的报道，只要收藏了就一定还在收藏夹里。
- **整份导出**：日报可「复制日报」得到纯文本（直接贴进微信群或邮件），也可「导出 .md」存成 Markdown 文件。精选、全部动态与星标三个信息流可按当前领域、分类与检索条件整份导出，单次最多 200 条，且始终从第一条开始，与当前翻到第几页无关。
- **单条复制**：每张卡片的「复制」一次取走标题与链接。
- **情报备忘**：「设置 → 情报备忘」的记录会列出最近 50 条，可随时回看与删除，保存在本机情报库中，不上传，也不受情报保留策略清理。

导出内容只接受绝对 HTTP(S) 链接，标题中的 Markdown 语法字符会被转义；另存为完全在本地完成，不经过任何外部服务。

### 每日研究归档

「设置 → 每日研究归档」提供一个默认关闭的自动保存开关。第一次开启时会弹出 Windows 原生文件夹选择窗口；只有用户选定且应用确认该目录可写后才会启用，渲染页面不能自行传入任意路径。也可以随时点击“保存本期”立即归档当前周期，失败后按提示重试。

归档以本机时区每天 **08:00** 为分界，日期 `D` 对应窗口为“前一日 08:00（不含）至当日 08:00（含）”，并按新闻实际采集时间 `fetched_at` 归属。目标结构如下：

```text
所选文件夹/
└─ 摘星阁新闻简报/YYYY/MM/YYYY-MM-DD/
   ├─ 新闻简报.md
   ├─ news.jsonl
   └─ manifest.json
```

- `新闻简报.md`：面向阅读的当日热点、可信技术突破、分类分组与完整行业索引。
- `news.jsonl`：窗口内采集到的**全部新闻记录**，包括相关、无关和待分析内容；每行一条结构化 JSON，适合后续自然语言分析、回测与模型迭代。
- `manifest.json`：版本、本地时区、UTC 偏移、时间窗口、数量统计、文件 SHA-256 与生成状态，用来判断一份档案是否完整、是否被修改。

写入先在同级临时目录完成，校验清单最后生成，再以一次目录重命名提交。完整的已有日期会直接跳过；若发现同名档案不完整或被修改，原目录会保留，并写入带“补存”时间戳的新目录，不静默覆盖证据。应用启动、系统唤醒或解锁后会按日期顺序补齐遗漏周期，并通过持久化游标每次轮转复核一个历史档案；这样长期覆盖全部日期，又不会在资料积累多年后阻塞式全量扫描。要准时保存，摘星阁需要在 08:00 运行，或之后再次启动；若开启“关闭主窗口后在后台运行”和登录自启，可减少漏存。

研究归档完全保存在用户选择的本地目录，不会由摘星阁自动上传，也不受数据库保留清理或桌面缓存治理影响。该目录的磁盘容量、访问权限、同步盘行为和备份由用户负责；包含新闻正文、链接、来源与模型研判，分享前请按所在组织的隐私和合规要求检查。

## 桌面后台运行

「设置 → 桌面运行」提供两个相互独立的开关，升级后均保持关闭：

- 关闭主窗口后在后台运行：关闭窗口时继续采集，可从系统托盘选择“打开摘星阁”；要彻底结束应用和本地后端，请在托盘菜单选择“退出摘星阁”。
- 登录 Windows 时自动启动：仅正式安装的 Windows 版本支持。若同时开启后台运行，登录后会静默启动；否则照常显示主窗口。

托盘初始化失败时，摘星阁会保留可见主窗口并显示固定提示，避免应用在没有恢复入口时隐藏。登录启动状态以 Windows 系统设置的回读结果为准，不写入 `ui-preferences.json`。这两项设置不会改变凭据加密、网络访问、AI 分析、数据保留或信源策略。

## 数据保留、存储治理与信源健康

摘星阁通常长期驻留运行，因此本地库需要有进有出。「设置 → 存储治理」会分开展示库内情报、待清理条目、情报数据库、可回收空页、桌面缓存、迁移残留、旧版数据与受管总计，并允许调整两档保留天数：

- 情报保留天数：默认 180 天，可设 7 到 3650 天
- 无关内容保留天数：默认 21 天，用于被判为无关的噪声；该值不会超过情报保留天数

清理每天在 08:00 日报与研究归档之后 25 分钟自动执行，也可以随时手动触发。到期条目连同 FTS5 全文索引行、公司关联与热度信号一起删除，没有成员的事件随之清理，随后运行 SQLite 索引优化并截断 WAL。日报是自包含快照，保留期独立且更长；用户选择的外部研究归档目录不在治理范围内。**已加星标的情报和情报备忘不参与清理，无论保留天数设成多少都会保留。**

数据库深度压缩用于回收 SQLite 文件内部已经空闲、但普通删除不会立刻归还给系统的页。手动点击「安全压缩」时会先后执行数据库完整性检查，并要求磁盘可用空间至少为主库体积的两倍再加 64 MiB。自动压缩更保守：只有可回收空间达到 **64 MiB**、占已分配空间至少 **25%**，且距离上次压缩至少 **30 天**时才会运行；采集、分析或普通清理进行中时会跳过，不会争抢数据库。

桌面缓存只治理 `Cache`、`Code Cache`、`GPUCache`、`DawnWebGPUCache` 和 `DawnGraphiteCache` 这些可再生成目录，软上限为 **256 MiB**，自动检查与清理最多每 7 天一次；占用中的缓存会记为待重启清理。超过 7 天、且名称精确匹配迁移临时文件规则的残留会自动删除，其他未知文件一律不碰。

旧版数据库绝不会自动删除。只有迁移满 **30 天**、当前数据库再次通过 `quick_check`、候选路径仍与迁移记录一致时，「审阅并清理」才会启用；点击后系统原生确认框会列出实际删除范围。删除范围只限旧数据库及同名 `-wal`、`-shm` 文件，不会删除整个目录。星标、情报备忘、普通设置、界面偏好和加密凭据始终受保护。

连续采集失败的信源会按指数拉长重试间隔（从一个采集周期起，上限 6 小时），成功后立即复位。信源页会显示暂停状态与连续失败次数，可点「立即重试」清除退避；点击右上角「立即采集分析」时始终忽略退避，全量重试一遍。

## AI 与隐私

默认的关键词启发式模式不调用 AI 服务。只有在设置页配置 API Key 后，摘星阁才会把待分析文章的标题、摘要等选定文本发送到你配置的模型服务；数据处理规则、费用和留存政策由该模型服务提供方决定。

API Key 不写入 `settings.json`，而是通过 Electron `safeStorage` 使用当前 Windows 用户的系统加密能力保存。更换电脑或 Windows 账户后，应重新输入 Key。

应用还会按功能需要访问用户启用的资讯信源、RSSHub、常用网址和 GitHub 更新服务。常用网址会交给系统默认浏览器打开；公开发行前必须确认其中不包含未经授权的内部链接。

每日研究归档只由桌面主进程写入用户通过原生弹窗选择的文件夹；目录路径和归档正文不会因为开启功能而发送给项目维护者。若目标位于 OneDrive、企业网盘或其他同步目录，是否上传由该目录自身的同步策略决定，不属于摘星阁的网络行为。

## 本地数据、备份与卸载

正式安装版数据位于 `%APPDATA%\摘星阁`，主要文件包括：

- `star-picking-pavilion.db`：信源、文章、日报和反馈
- `settings.json`：不含 API Key 的普通设置
- `credentials.v1.json`：由 `safeStorage` 加密的 AI 凭据
- `ui-preferences.json`：版本化的界面选择，不含 API Key、搜索词或未提交表单
- `appearance/wallpaper.asset`：可选的自定义界面壁纸，经压缩与格式校验后独立保存
- `daily-archive.json`：每日研究归档的开关、用户所选目录、已成功日期与待补齐状态，不含新闻正文或秘密
- `migration-v0.0.1.json`：旧版数据迁移记录，不含秘密
- `storage-maintenance.json`：缓存清理与数据库维护时间记录，不含情报正文或秘密

备份前请完全退出摘星阁，再复制 `%APPDATA%\摘星阁\star-picking-pavilion.db`、需要的设置文件和可选的 `appearance\wallpaper.asset`；如已开启每日研究归档，还应单独备份所选目录下的 `摘星阁新闻简报`。恢复数据库时也应先退出应用。跨电脑恢复后，建议运行应用确认数据库完整性、重新选择归档目录并重新配置 API Key。

超过保留天数的文章会被自动清理，若需要长期归档请提前备份，或把保留天数调高。

卸载程序会保留 `%APPDATA%\摘星阁` 中的用户数据，方便重装或升级。若确实不再需要这些数据，请在确认备份后由用户自行删除该目录。

旧版 `%APPDATA%\捕风司\windcatcher.db` 或旧“摘星阁”数据库会在首次启动时通过 SQLite 一致性备份迁移；原文件不会被覆盖。迁移满 30 天且当前库健康后，可在「设置 → 存储治理」中审阅精确文件清单并手动确认删除。

从 v0.0.12 及更早版本升级时，技术突破相关数据库字段采用向前兼容的增量迁移自动补充；既有文章、星标、日报、备忘、设置、凭据、保留策略和界面偏好均保留。每日研究归档默认关闭，不会在未选择文件夹时写入任何外部目录。

## 安全模型

- 桌面后端只监听 `127.0.0.1` 的随机端口，并由每次启动生成的随机令牌保护 API。
- 渲染进程启用 sandbox、上下文隔离和严格 CSP，默认拒绝摄像头、麦克风、定位等权限。
- 远程链接和图片只允许绝对 HTTP(S) URL，外链由系统浏览器打开。
- 请求体限制为 64 KiB，配置文件采用原子替换，数据库启动时运行完整性检查。
- 安装包使用严格文件白名单并扫描 ASAR，数据库、日志、工作树和本机配置不会被打包。

安全问题请按 [SECURITY.md](SECURITY.md) 私下报告，不要在公开 Issue 中披露尚未修复的漏洞。

## 从源码开发

需要 Node.js 22.19+ 与 npm 10+。

```powershell
npm ci
npm test
npm run test:e2e
npm run audit:runtime
npm start
```

常用维护命令：

```powershell
npm run server              # 独立开发服务器，默认 http://127.0.0.1:7644
npm run pipeline            # 手动采集、判断与写作、事件归组
npm run eval:selection -- --gold data/gold.jsonl  # 用自标注样本校准精选门槛
npm run audit:sources -- --strict # 在隔离数据目录实时复查全部启用信源
npm run dist                # 生成 Windows 安装包，不发布
npm run verify:package      # 审计 ASAR、文件边界和体积
npm run verify:version -- --tag v0.2.0 --artifacts
npm run notices
```

桌面模式使用随机端口；上面的 7644 只用于显式运行独立开发服务器。发布步骤与隐私门禁见 [RELEASING.md](RELEASING.md)。
