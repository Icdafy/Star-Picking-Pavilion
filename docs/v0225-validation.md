# v0.2.25 验证记录

日期：2026-10-07（北京时间）。本次修复用户反馈的“全部动态”出现其他行业信息。模型调用验证仅使用模拟端点及测试凭据；本机数据先只读检查，再用 SQLite 备份生成隔离副本验证迁移，未修改用户正在使用的原数据库。

## 根因与影响

1. `server/index.js` 原条件是 `(a.relevant IS NULL OR a.relevant = 1)`。综合媒体所有原始条目入库时 `relevant` 为 NULL，采集完成但尚未行业判断、模型等待、预算暂停或失败时会提前显示。v0.2.23 tag 已存在同一条件，v0.2.24 沿用，没有证据支持将问题全部归因于本次 AIHOT 适配。
2. `server/collectors/index.js` 未在统一入库入口进行行业粗过滤。普通 RSS、HTML 与通用 API 的无关条目也会先补抓正文、入库，之后才由分析管线排除，扩大提前显示的噪声范围。
3. 通用财经合集的检索摘要有时只摘录其中的航天段落。实际旧库中“假期重点速递”等跨行业合集已获模型 PASS；原噪声计数与预筛未可靠阻断这种主旨错配。
4. 词库和关键词守卫只做包含匹配，会把英文单词中的 ULA／SES 与“千亿航天”中的“亿航”误识别成具名主体。公司关联层已有词边界规则，但行业过滤未共用。
5. 模型预筛 PASS 接受缺失或非法领域，持久化又允许回落信源领域乃至默认 `lowaltitude`，缺少已确认两行业结论的约束。旧预筛回执也须校验领域，避免缓存跳过新版解析规则。

## 修复边界

- 全部动态、精选、信息流导出与词库计数共用“相关、判断完成、领域合法”的 SQL 条件；相关／精选统计同步收紧。待判资料保留在分析队列，星标继续服从用户显式收藏。
- 普通媒体明显无关内容在正文补抓与入库前过滤；官方和海外陌生主体在已配置模型时仍可排队，不提前进入普通信息流。
- 明确的通用财经合集在采集和分析入口阻断，行业早参保留。英文及短中文别名与公司匹配共用边界规则，采集关键词守卫同步使用。
- 模型 PASS 必须明确指定 A 或 B；持久化不再用信源领域或默认低空领域冒充确认结论。未知答复沿用原重试与启发式降级流程。
- 启动时幂等复核旧库：撤回明确合集、重新排队错误启发式／非法领域／未完成旧标记；保留原文、原分析、时间、星标、归档与设置。撤销相关热度信号、重选事件主条并使旧综述失效。合法模型结论不会仅因陌生标题而被词库推翻。
- 无新增依赖，无用户数据库、配置或验证日志进入 Git 与安装包。
