# v0.3.0 验证记录

本版是大版本更新：侧栏“情报工作区”更名为“工作区”，并把独立开发的提示词仓库“藏言录”作为完整模块并入摘星阁，排在常用网址下方。情报采集、分析、出刊与信源均未改动。

## 实现

- **随包原样附带**：`electron/cangyanlu/藏言录.html` 与藏言录原始单文件逐字节一致（1,120,110 字节，SHA-256 `01c4e22b6d4f8cdc82dfb8fcd8a152d6add6db1186bc69096c431965c9bbc3c8`，只含 LF）。`.gitattributes` 对其设 `-text`，防止 Windows 检出把 LF 改成 CRLF；校验和与字节数由 `test/cangyanlu.test.js` 锁定，主进程从安装包内读取后通过协议响应逐字节返回。
- **固定来源与独立分区**（`electron/cangyanlu.js`）：ready 前把 `cangyanlu` 注册为标准安全协议；分区 `persist:cangyanlu` 只响应 `cangyanlu://app/` 的 GET/HEAD，其余 404/405，附 `default-src 'none'` 的独立 CSP。来源固定，因此 localStorage 与 IndexedDB 不随后端每次启动的随机端口变化。权限只放行藏言录来源的 `clipboard-sanitized-write`、`fileSystem`、`persistent-storage`；请求白名单只认藏言录自身、Google Fonts 标题字体子集与 `data:`/`blob:`。
- **webview 守卫**：主窗口开启 `webviewTag`，`will-attach-webview` 只放行固定地址与分区，删除预加载并强制沙箱、上下文隔离与禁用 Node。guest 的外链交给系统浏览器；`window.open` 放行一个不显示的空壳并立即销毁，页面拿到句柄，“复制并打开”不再误报被拦截；离开藏言录的导航被接管。guest 内的 Alt+数字经 `before-input-event` 转发给工作区。
- **工作区接入**（`renderer/cangyanlu-controller.js`，第 30 个脚本边界）：视图 `prompts` 首次进入才挂载 webview；高度按吸顶塔台（宽屏）或吸顶导航（窄屏）下沿铺到视口底端，窄屏进入时滚到紧贴吸顶导航处；加载失败或进程退出给出“重新载入”，浏览器开发模式只显示说明。G P 跳转、命令面板别名；`Shortcuts.ALT_VIEWS` 让 Alt+1…0 保持原有十个视图。视图偏好枚举加入 `prompts`，重启可回到藏言录。
- **命名**：侧栏分组“工作区”、底部标识“本地工作区”，README 同步；历史版本说明保持原文。
- **预算与声明**：脚本 29 → 30，CSS 约 333.2 KB / 336 KiB（CI 口径），关键帧 20/20、backdrop-filter 10/10 未增；第三方声明新增 three.js r158（MIT，藏言录内联）。无新增 npm 依赖。

## 边界

- 藏言录运行在独立分区，数据不进入情报库，也不在“存储治理”的缓存清理范围内；备份请用藏言录「管理 → 数据与备份」导出 JSON，或绑定本地文件同步。
- 焦点在藏言录内时，只有 Alt+数字转发给工作区；Ctrl+K、/、G 等组合键归藏言录自己（它有自己的搜索与快捷键）。
- 没有可用 WebGL 的环境下，藏言录按自身设计降级为不显示小岛，列表与编辑照常可用。
- 浏览器开发模式（`npm run server`）不提供固定来源与本地分区，藏言录视图只显示说明。
- 安装包沿用未签名策略；安装、启动、单实例、退出、卸载与用户数据保留在一次性 Windows CI 执行，本机不运行安装器。
