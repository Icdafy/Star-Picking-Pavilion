# 外部内容导入（v0.2.1 后续分支，尚未包含于安装包）

该入口补充 AIHOT 的 external 能力：公开订阅转换器、自有抓取脚本或人工整理的文章，均可送入现有清洗、URL 判重、分析及归组流程。导入接口只写原始内容，不调用模型、不接受客户端指定的评分或精选结论。

## 在应用中使用

1. 打开“信源 → 提报信源”，类型选“外部内容导入”，名称填写实际出版方或采集项目，地址填写唯一标识，如 `external://my-news`。
2. 在新信源卡片点击“导入内容”，粘贴文章 JSON 数组。
3. 导入历史资料时勾选“作为历史回灌”。结果显示新增和重复条数，失败时保留原输入。
4. 等待常规采集分析，或使用应用的“立即采集分析”。停用该信源会阻止后续导入，但保留既有文章。

```json
[
  {
    "title": "原文标题",
    "url": "https://example.com/news/123",
    "publishedAt": "2026-09-29T08:00:00+08:00",
    "summary": "原文摘要",
    "contentText": "可选的已取得正文",
    "backfill": true
  }
]
```

这不是微信验证绕过工具，也不会自动取得受限正文。“商业航天发展”三篇用户提供原文截至本次核验仍不可读取，不能因此把它计为采集成功的信源。

## 脚本接口

服务端仅监听 `127.0.0.1`。使用 `POST /api/ingest/items`，`Content-Type: application/json`，请求体为 `{"sourceId": 数字编号, "items": [...]}`。先通过信源页或 `/api/sources` 创建启用的 `external` 类型源；该接口不会悄悄新建、启用或改名信源。

所有请求沿用本机 API 鉴权。单独运行 `npm run server` 时，可由启动者通过环境变量 `STAR_PICKING_PAVILION_API_TOKEN` 设置私密令牌，脚本在 `x-star-picking-pavilion-token` 请求头发送相同值；不要把令牌放入 URL、正文或仓库。桌面版由应用管理临时令牌，普通用户直接使用导入弹窗即可。

限制和时间语义：

- 每批 1–50 条，整个 JSON 请求最多 64 KiB；每分钟最多 10 次，跨信源共用限额。
- `title`、无内嵌凭据的 HTTP(S) `url` 必填。摘要最长 4,000 字符，正文最长 12,000 字符。
- 发布时间选填；填写时须为含时区的有效 ISO 时间，不接受明显未来时间。未填则保留未知，不编造发布日期。
- 先校验整批格式，再逐条入库。带跟踪参数的重复 URL 不会产生新文章，重复提交返回 `duplicates` 数量。
- `backfill: true` 或 AIHOT 兼容字段 `raw._aihot.backfill: true` 会持久保留历史标记，后续分析或旧簇迁移均不会清除它。已发布超过行业配置历史窗口的文章也标为历史。
- 外部源不参与定时网页抓取，空闲时显示“等待导入”，不会因未抓取产生虚假的成功记录。

此实现是本机桌面适配。未提供公网监听、上游独立 Bearer INGEST_TOKEN、自动建源与隔离发布队列，不应被描述为上游 HTTP 协议的逐字兼容。

验证覆盖：`test/external-ingest.test.js` 的鉴权、边界、判重、历史回灌、限流、无模型调用与定时跳过，以及 `test/e2e/external-ingest.test.js` 的真实 Electron 创建、错误恢复、导入、重复提交、停用和窗口布局。
