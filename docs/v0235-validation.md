# v0.2.35 新闻推送：实现与发布验证

2026-10-16（北京时间）。基线为 v0.2.34 收尾提交 `205f711`。本版在设置页新增“新闻推送”一节：绑定飞书、钉钉或 QQ 机器人后，按用户设定的节奏把新入选的情报推送到手机。所有测试使用隔离数据目录与本机桩服务，不修改用户正式数据，也不向真实机器人发送消息。

## 协议依据（2026-10 核对）

| 渠道 | 接口 | 鉴权 / 加签 | 成功与常见错误 |
| --- | --- | --- | --- |
| 飞书 | `POST https://open.feishu.cn/open-apis/bot/v2/hook/<token>`（Lark 为 `open.larksuite.com`） | `timestamp` 为秒；`sign = Base64(HmacSHA256(key = timestamp + "\n" + secret, message = ""))`，写入请求 JSON | `code = 0`；19021 签名/时间、19024 关键词、19022 IP 白名单、11232 限流；请求体 ≤ 20 KB，100 次/分钟、5 次/秒 |
| 钉钉 | `POST https://oapi.dingtalk.com/robot/send?access_token=<token>` | `timestamp` 为毫秒；`sign = urlEncode(Base64(HmacSHA256(key = secret, message = timestamp + "\n" + secret)))`，拼到查询串 | `errcode = 0`；310000 安全设置（关键词 / 签名 / IP），130101 发送过快；每个机器人每分钟 20 条 |
| QQ | OneBot v11 HTTP：`POST {base}/send_private_msg`、`/send_group_msg` | `Authorization: Bearer <access_token>` | `status = ok` 且 `retcode = 0` |

QQ 开放平台的机器人从 2025-04-21 起不再支持主动推送（[官方发送消息文档](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/send-receive/send.html)），所以个人定时推送改用社区通行的 OneBot v11 协议，由 NapCat（推荐）、Lagrange 或 LLOneBot 提供本机或局域网 HTTP 服务。Qmsg 酱这类转发服务会删除消息里的网址，不适合新闻推送，没有采用。飞书依据[自定义机器人使用指南](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot)；钉钉依据开放平台的自定义机器人安全设置与消息类型说明。

## 设计

- **绑定**：`POST /api/push/channels/:id/bind` 先在本机校验连接信息（飞书和钉钉只接受官方主机与路径；QQ 公网地址必须用 HTTPS，本机或局域网允许 HTTP），再向机器人发送 6 位验证码。连接信息只在内存保存 10 分钟。`/verify` 用常量时间比较，最多错 5 次，通过后才经设置协调器的同一事务队列写入凭据包（键为 `push-<渠道>`，Windows safeStorage 加密）。重新绑定失败时，已有的连接信息保持不变。`push-` 前缀不能再用作模型提供商 ID。
- **节奏**（`server/push/schedule.js`，纯函数）：每隔 N 分钟模式只提供能整除 24 小时的档位（15、30、60、120、180、240、360、480、720、1440），按起始时刻对齐；每天固定时刻模式最多 12 个时刻。两种模式都受推送日和免打扰时段约束（免打扰可以跨午夜），落在免打扰里的时刻直接跳过。开启推送、绑定或重新启用渠道、保存节奏时，游标都重置为当前时间，不会把已经过去的时刻补推出去。关机错过的时刻只补推最近一次，并且只在 24 小时内补推。
- **选稿**：口径与“精选 / 全部动态”一致（行业可见、翻译完成、事件簇只取主条），回看窗口为 36 小时（间隔超过 18 小时时取两倍间隔）。按热度排序后截取条数。`push_deliveries` 按渠道记录已推送的文章和事件簇，主条更替后同一事件也不会重复推送。推送失败的条目不会被记为已送达。
- **投递**：不跟随重定向，响应体上限 64 KB，超时 15 秒，退出时会中止请求。限流、5xx 和网络错误按 4 秒、15 秒退避重试两次。标题与摘要里的 Markdown 控制字符换成全角字符，链接只放行 http(s)，括号和空白做百分号编码。飞书和钉钉的请求体超过 18 KB 时从末尾舍弃条目；QQ 消息每段约 1500 字，最多分 4 段。
- **生命周期**：推送计时器跟随后端调度启动；关闭时先停止计时器并中止请求，等推送真正结束后才关闭数据库。设为 `NO_SCHEDULER=1` 的测试环境不会启动推送计时器。
- **界面**：新增“04 新闻推送”章节，设置导航共 10 个章节。全部沿用现有组件样式，CSS、脚本标签与关键帧预算均未增加（脚本仍为 27 个，控制器并入 `settings-form-controller.js`）。

## 测试

| 层面 | 证据 |
| --- | --- |
| 协议 | 飞书和钉钉加签与独立计算的 HMAC 逐字相等；拒绝伪造主机、查询串、内嵌凭据和非 HTTPS；QQ 私聊和群聊接口、Bearer 头；错误码转成中文建议并标记是否可重试 |

| 服务 | 验证码送达前不落盘、错码限次、过期失效、失败的重新绑定不覆盖已有连接；热度排序、非精选和超窗过滤、事件簇主条更替后不重复；限流重试、失败不记为已送达；定时推送、补推、开启时不补推 |
| API | 真实后端子进程配合本机 OneBot 桩完成验证码绑定、节奏保存、立即推送（空库不打扰）、测试推送、暂停和解绑；Token 与完整 QQ 号不出现在 `/api/push`、`/api/settings`、`/api/models` 和 `settings.json` 中 |

## 限制

- 推送由本机摘星阁发出，电脑需要开机并运行摘星阁（可以开启后台运行与登录启动）。推送内容来自已采集分析的情报，建议同时开启自动采集分析。
- 飞书、钉钉和 QQ 平台本身的限流、风控、群设置和账号状态由各平台决定。QQ 通过第三方 OneBot 实现登录个人账号，存在平台风控风险，建议使用小号。
- 本版没有向真实的飞书、钉钉或 QQ 机器人发送消息，协议正确性依据官方文档和独立计算的签名断言。首次绑定时的验证码流程本身就会在真实平台上验证一次端到端链路。
