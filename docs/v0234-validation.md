# v0.2.34 审查、性能与发布验证

2026-10-16（北京时间）。基线为v0.2.33收尾提交 `b27daa2`。本版解决“立即采集分析”首条结果等待过久，并复核前端、调度、模型、采集、数据库、接口、桌面生命周期及发布工程。回归使用隔离目录，不修改用户正式数据或密钥。

## 根因与修复

- 调度原先等待所有信源和历史日期修复后才分析。现在单一消费者处理积压、随每个信源事务提交唤醒，小批次完成归组即可读，慢源继续采集。每轮仍最多分析2400条；完成时重新统计队列，包含达到上限后慢源新入库的文章。
- AI原先整批预筛结束后才评分。现在预筛与三个评分worker通过有界队列交叠，保留每条两次独立评分、内容理解、行业门槛、预算和付费回执。全事件合并、综述与历史时间修补在整轮末尾完成一次。修复UNKNOWN补正文和仅有翻译进展时提前结束，以及翻译/归组/综述预算状态遗漏。
- 国内立即采集，海外探测并行且仍须通过后才访问海外源。源并发4、每源补抓2、公众号节流及201源目录不变。同轮canonical正文/日期共享请求，成功缓存最多512项；正文在途和robots请求单飞，失败可重试。公众号已核验全文直接复用；历史10条日期修复最多两项并发。分支失败也等待在途任务退出后才放锁，不跨网络等待持有事务。
- 前端显示采集、分析、归组、综述阶段及信源/新增/已分析/精选数。任务中1.5秒、空闲18秒、后台手动跟踪5秒自调度，单一在途轮询。防止POST前旧在线响应误报完成，SSE完成在请求在途时排队补跑；后台完成后前台调和，展开阅读时提示更新。POST和统计同时失败后按钮恢复重试。
- 统计缓存检查 `total_changes()` 与 `data_version`，提交即失效，保留5秒TTL处理跨日。四个索引分别覆盖信源待译统计、待分析顺序、已确认行业信息流和精选时间排序。真实执行计划确认避免全库重复扫描及临时排序，结果与无索引查询逐项一致，包括混合时区。
- `quick_check` 的BUSY、I/O、权限等操作错误不再触发损坏隔离；只有已证实损坏才执行保留恢复。后端退出消息发送异常、kill失败或无退出确认都有界报错，清理定时器并可重试；未确认关闭不会启动更新安装器。

无新增运行依赖。未删除信源、缩小采集范围或省略双评分。情报、FTS、星标、归档、公司/融资、预算回执、凭据和UI偏好沿用原有保护。
