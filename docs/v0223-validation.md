# v0.2.23 验证记录

日期：2026-10-07（北京时间）。本次范围为报道发布时间、新闻时间轴与采集间隔。验证使用隔离数据目录，用户数据库仅只读定位问题；模型密钥不参与验证。

## 问题定位

用户报告的官网融资报道确实在北京时间 2026-10-07 01:14:27 收录，而 published_at 为空、content_status=ok、timing_repair_version=3、historical=0。原文 [星河动力航天完成24亿元D轮融资](https://www.galactic-energy.cn/index.php/Show/cid/11/aid/269) 的正文标题后 h3 明确写着 2025/09/30。官网首页列表没有日期。

原正文解析只匹配日期加时分，未匹配标题后独立日期；正文已处理及事件修复完成又阻止后续补查。新闻流 SQL 和前端分组优先取 event_date，使报道时间与事件时间混用。同日增量前置插入只比较日期分组，较旧报道可能被放在较新报道之上。

采集原为固定 setInterval，手动全量任务没有重置原定采集时钟；每 75 秒的分析循环也会让已采集资料陆续进入可见列表，塔台却统一显示“采集中”，造成再次采集的误解。

## 修复范围

- 缺日期时在入库前请求原文发布信息；无 API Key 同样执行，网络等待和确实无日期仍允许入库。HTTP 请求在 SQLite 事务外执行，响应到达后再次核对信源的启停与配置。
- 对已收录且仍缺发布时间的启用信源新闻独立补查，包含正文已处理和事件修复 v3 的记录。最近检查过的未知记录退避 24 小时；网络等待不消耗检查时间。保留已有发布日期、首次收录时间、分析、星标及来源身份。补齐旧文同步调整历史标记并移除新近热度信号。
- 读取发布元数据、文章 JSON-LD 与专门日期元素；年月日、年月、月日按原精度保存。月初仅作为月份级排序锚点，显示及导出明确说明“仅确认月份”；月日缺年份显式标记推定，跨年回溯，明确 URL 年份优先。无时分不显示虚构零点，无效日历拒绝。
- 普通新闻流以报道发布时间排序和分组，无日期回落采集时间并标注；事件发生日仍作为独立辅助信息。时间轴分组、时分和远期日期使用北京时间，不随操作系统时区漂移。星标视图沿用收藏时间，日报与刊期归档沿用采集窗口，每篇记录保留发布时间及精度。
- 融资列表的报道日期按北京时间转换，2025/09/30 不再截取 UTC 字符串而显示成 9 月 29 日；月份级报道显示年月和“仅月份”，筛选与日期列同口径。
- 采集改为完成后 setTimeout 自调度；修改采集间隔立即生效，手动任务接管旧采集与启动时钟，完成后重新等待完整间隔。分析循环保留独立计时。1—720 整数分钟在表单、设置接口、持久化及运行时同口径。
