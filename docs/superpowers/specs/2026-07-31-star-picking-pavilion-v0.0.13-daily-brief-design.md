# 摘星阁 v0.0.13 每日新闻简报与技术突破热度设计

## 背景

摘星阁当前公开版本是 v0.0.12。产品已经能够持续采集低空经济与商业航天新闻，完成相关性预筛、五维评分、事件聚类、精选判定、热点排序和每日情报日报，并允许用户手动把日报或当前列表导出为 Markdown/纯文本。

现有日报仍有四个缺口：

1. 每天 8 点生成的日报只保存在应用数据库，且只纳入达到精选阈值的事件簇主条；它不是可独立保存、可长期积累的完整研究样本。
2. 用户只能逐次手动下载，不能授权一个目录后按日自动落盘。
3. 应用在 8 点没有运行时不会补齐错过的日报，保存失败也没有持久化状态。
4. 当前热度只等于质量分乘以时间衰减，无法显式识别低空经济与商业航天中的可信技术突破。

这会限制用户对历史新闻进行后验分析：人可以阅读已有日报，但算法缺少逐条、结构化、带原始评分状态的每日样本，难以回看哪些事件后来形成多源增长、哪些只是未经证实的单点声明。

## 版本决定

v0.0.12 已于 2026-07-31（北京时间）公开发布，内容是存储治理。为避免重写公开标签、破坏自动更新历史和已下载资产，本功能发布为 **v0.0.13**。

## 目标

v0.0.13 要实现：

1. 在本地时间每天 8:00 固定生成前 24 小时的新闻简报。
2. 在设置页提供默认关闭的自动保存开关；首次开启必须弹出系统目录选择窗口。
3. 每日同时产出适合阅读的 Markdown 简报和适合后续 NLP 的 JSONL 全量样本，并用清单记录格式、窗口和校验值。
4. 应用错过 8 点时在下次启动后补齐，保存失败时可诊断、可重试且不伪报成功。
5. 对低空经济和商业航天的可信技术突破增加可解释、可配置、受证据约束的热度提升。
6. 将代码、文档、测试、安装包、标签和 GitHub Release 全部统一到 v0.0.13。

## 非目标

- 不抓取或转载新闻网站的完整网页正文。归档保存摘星阁已经合法采集并入库的标题、原始摘要、链接和分析结果。
- 不调用大模型生成每日简报；简报必须在未配置 API Key 或模型暂时不可用时照常生成。
- 不上传简报、目录路径或历史新闻到云端。
- 不修改用户选定目录以外的文件，不递归清理用户归档。
- 不把“出现突破、首飞”等单个宣传词直接等同于技术突破。
- 不把技术突破加权混入可信度分，不让低可信传闻借加权进入热点。
- 不实现未来真假标签的自动裁决；本版本只保存足以进行后验比较的原始特征、评分和事件簇证据。
- 不覆盖已经存在的日期归档；用户编辑过的历史文件始终保留。

## 方案比较

### 方案 A：只保存 Markdown

每天保存一份包含全部条目的 Markdown。

优点是实现和阅读最简单；缺点是长文档臃肿，字段结构不稳定，不适合作为长期 NLP 数据集。

### 方案 B：只备份 SQLite 数据库

每天复制一份数据库。

优点是字段最完整；缺点是磁盘占用增长快，普通同事无法直接阅读，数据库快照还会重复保存绝大多数历史数据。

### 方案 C：Markdown 简报 + JSONL 样本 + manifest（采用）

每天创建独立目录，保存一份人读简报、一份一行一条的机器数据和一份清单。

优点是阅读、检索、版本化分析与增量存储兼顾；缺点是需要新增归档协议、原子写入和桌面调度测试。该成本与用户长期积累研究样本的核心目标直接相关，因此采用。

## 总体架构

功能分为四个边界清晰的组件：

1. **每日数据集生成器（后端）**：按固定窗口查询数据库，生成确定性的简报模型和 JSONL 记录，不接收也不访问任意文件路径。
2. **每日归档服务（Electron 主进程）**：拥有目录选择和文件写入权限，通过受认证的本地后端接口获取数据包，负责调度、补齐、原子落盘和状态持久化。
3. **归档设置控制器（渲染层）**：只显示状态并发起固定 IPC 动作，不能向主进程提交任意路径。
4. **技术突破判定器（后端分析层）**：从领域、类别、模型维度、技术对象、完成动作、信源与多源印证中计算技术突破强度，把结果持久化并供热点、卡片和归档共用。

后端只决定“保存什么”，Electron 只决定“保存到哪里”。渲染层既不能读取文件系统，也不能伪造保存目录。

## 1. 每日窗口与日期语义

日期 `YYYY-MM-DD` 表示以该日期 8:00 为截止点的归档：

- 开始：前一自然日 8:00，开区间；
- 结束：当日 8:00，闭区间；
- 使用操作系统本地时区，与现有日报和界面日期保持一致；
- 数据集纳入条件按 `fetched_at` 判断，而不是按 `published_at` 判断。

按采集时间归档可以保证每条进入摘星阁的记录只属于一个日窗口。新闻在原站发布时间较早但被信源延迟发现时，仍会在实际采集日进入归档，不会因为发布时间落在旧窗口而永久遗漏。每条记录同时保留 `publishedAt` 与 `fetchedAt`，后续研究可自行选择口径。

## 2. 简报内容

Markdown 简报按以下顺序组织：

1. 时间窗口、生成时间、全量采集数、相关数、精选数和待分析数；
2. 低空经济与商业航天分领域统计；
3. 当日热点排行；
4. 可信技术突破；
5. 政策法规、发射与任务、技术研发、企业动态、资本市场、应用场景、观点报告；
6. 未达到精选阈值但属于行业的完整索引；
7. 无关或尚待分析记录的数量说明；
8. 数据文件说明与摘星阁版本。

热点与分类摘要按事件簇折叠，避免同一事件在可读简报中重复占位；JSONL 不折叠，保留全部原始报道，方便后续研究报道扩散速度和多源增长。

简报生成不依赖大模型。已经分析的新闻使用 AI 摘要或启发式摘要，未分析新闻退回原始摘要；没有摘要时仍保留标题、来源、时间和链接。

## 3. JSONL 研究数据

`news.jsonl` 使用 UTF-8，每行一个 JSON 对象。顶层字段固定，缺失值写 `null`，数组写空数组，不随界面文案变化。

每条记录至少包括：

- `schemaVersion`
- `archiveDate`
- `windowStart`
- `windowEnd`
- `articleId`
- `sourceId`
- `sourceName`
- `sourceTier`
- `title`
- `url`
- `rawSummary`
- `aiSummary`
- `aiReason`
- `publishedAt`
- `fetchedAt`
- `domain`
- `category`
- `relevant`
- `analyzed`
- `scores`
- `quality`
- `heatAtCutoff`
- `featured`
- `tags`
- `clusterId`
- `clusterSize`
- `starred`
- `lexiconTerms`
- `lexiconWeight`
- `noiseHits`
- `breakthroughScore`
- `breakthroughBonus`
- `breakthroughSignals`
- `scoringVersion`

归档不包含 API Key、凭据、用户搜索词、备忘、设置文件路径或其他私人数据。

## 4. 目录结构与清单

用户选择根目录后，应用创建：

```text
<根目录>/
  摘星阁新闻简报/
    2026/
      07/
        2026-07-31/
          新闻简报.md
          news.jsonl
          manifest.json
```

`manifest.json` 包含：

- 归档协议版本；
- 摘星阁版本；
- 本地时区；
- 时间窗口；
- 记录数、相关数、精选数、技术突破数；
- 每个文件的字节数和 SHA-256；
- 生成完成时间。

文件名固定，不使用新闻标题拼接路径，避免 Windows 保留字符、超长路径和路径注入。

## 5. 开关与设置体验

“设置 → 每日新闻简报”新增：

- “每天 8:00 自动保存”开关，默认关闭；
- 当前保存位置（中间路径可折叠显示，完整路径用于辅助提示）；
- “更换位置”按钮；
- “立即保存本期”按钮；
- 最近成功、最近失败、下一次计划时间和待补齐数量。

首次打开开关：

1. Electron 弹出原生目录选择窗口；
2. 用户选择后才保存设置并把开关置为开启；
3. 用户取消时开关保持关闭；
4. 选择不可写目录时提示原因，不保存无效设置。

关闭开关只停止新的自动保存，不删除历史归档，也不清空已授权路径。再次开启时可沿用原路径；若原路径不可用则要求重新选择。

“立即保存本期”保存最近一个已经到达截止点的窗口。例如 7 月 31 日 10:00 点击时保存 `2026-07-31`；7 月 31 日 7:00 点击时保存 `2026-07-30`。若目标日期已成功归档，界面明确显示“已存在”，不覆盖。

纯浏览器运行时保留现有手动 Markdown 下载；自动本地归档开关禁用并说明仅桌面版可用。

## 6. 8 点调度与错过补齐

归档服务使用单次定时器对齐下一个本地 8:00，而不是每 24 小时固定间隔，避免夏令时或系统休眠造成漂移。

触发规则：

- 8:00 到达时为当天日期建立任务；
- 任务先向后端请求固定截止窗口的数据包，再落盘；
- 同一日期只允许一个任务运行；
- 归档不与数据库写入共享文件锁，后端查询使用短事务快照；
- 应用启动、从休眠恢复和系统时间变化后重新计算下一次 8:00。

归档状态保存：

- `enabled`
- `rootDirectory`
- `enabledAt`
- `lastSuccessfulDate`
- `lastAttemptAt`
- `lastErrorCode`
- `lastErrorAt`
- `schemaVersion`

应用启动且自动保存开启时，从 `enabledAt` 对应的首个到期窗口开始，逐日补齐到最近已到期窗口。已存在完整 `manifest.json` 且校验通过的日期跳过；缺文件、校验失败或临时目录残留的日期重新生成到新的暂存目录。

补齐按日期串行运行，避免大量数据库查询和磁盘写入同时发生。失败日期不推进 `lastSuccessfulDate`，下次启动或用户点击重试时继续。

## 7. 原子写入与冲突规则

每个日期先写入同级、随机命名的暂存目录：

1. 写 `新闻简报.md`；
2. 流式写 `news.jsonl`；
3. 计算两者 SHA-256；
4. 最后写 `manifest.json`；
5. 刷新并关闭文件；
6. 把暂存目录原子重命名为正式日期目录。

若正式日期目录已经存在：

- manifest 完整且文件校验一致：返回“已归档”，不重写；
- 目录存在但内容不完整：不删除用户目录，改用 `2026-07-31-补存-<时间>` 保存并提示冲突；
- 不使用递归覆盖或静默删除。

应用异常退出只会留下可识别的暂存目录。下次启动可以重新生成，但不会把暂存内容当成成功归档。

## 8. IPC 与路径安全

preload 只暴露固定方法：

- `getDailyArchiveSettings()`
- `chooseDailyArchiveDirectory()`
- `setDailyArchiveEnabled(enabled)`
- `saveCurrentDailyArchive()`
- `retryDailyArchives()`

目录选择不接收渲染层路径。主进程从 Electron `dialog.showOpenDialog` 的返回值中取得目录，解析真实路径并验证：

- 绝对路径；
- 可创建并写入探测文件；
- 不是文件；
- 目标子目录解析后仍位于授权根目录；
- 不经过会把目标引出根目录的目录联接或符号链接。

后端归档接口只接受严格的 `YYYY-MM-DD` 日期和固定格式，不接受路径、SQL、命令或任意模板。

状态文件使用临时文件加原子重命名，损坏时回退为关闭状态，不猜测或扫描任意目录。

## 9. 技术突破判定

新增独立、可测试的技术突破判定器。它不以单个关键词下结论，而是形成 0 到 1 的 `breakthroughScore`。

### 必要条件

新闻必须同时满足：

1. 领域是 `lowaltitude`、`aerospace` 或 `both`；
2. 分类是“技术研发”或“发射与任务”；
3. 文本中同时存在至少一个技术对象和一个完成/验证动作；
4. 不属于噪声形态；
5. 可信门槛通过。

技术对象按领域维护在独立配置中。例如：

- 低空经济：eVTOL、飞行汽车、飞控、航电、适航、电推进、航空电池、复合翼、垂直起降、低空通信导航监视、低空智联网、无人机系统；
- 商业航天：可重复使用火箭、发动机、推进系统、回收复用、卫星平台、有效载荷、星座组网、入轨、测控、热防护、发射台、轨道转移。

完成/验证动作包括首飞、试飞完成、点火成功、入轨、回收成功、复用、适航取证、交付、量产下线、测试通过、性能验证、刷新纪录等。

“拟、计划、有望、或将、传闻、网传、概念、预计、意向、宣布将”等不确定表达会抑制分数；只有同一句或标题中同时存在明确完成证据时才允许恢复。

### 可信门槛

满足任一项：

- 信源为 T1；
- 信源为 T1.5 且模型可信度不低于配置阈值；
- 事件簇至少有两个不同信源印证且模型可信度不低于较低阈值。

无模型时使用更保守规则：必须是 T1，或至少两个不同信源印证；T2 单点声明不加分。

### 强度

在必要条件通过后，强度由以下证据归一化得到：

- 新颖度；
- 重要性；
- 可信度；
- 完成动作强度；
- 技术对象专属性；
- 信源等级；
- 多源印证；
- 不确定表达惩罚。

判定结果持久化：

- `breakthrough_score`：0 到 1；
- `breakthrough_bonus`：实际热度加分；
- `breakthrough_signals_json`：命中的对象、动作、可信证据、抑制原因和规则版本。

事件聚类后必须重新计算，因为多源印证会改变可信门槛和强度。

## 10. 热度公式

当前公式：

```text
热度 = 质量分 × 0.5 ^ (距发布时间小时数 / 基础半衰期)
```

v0.0.13 公式：

```text
突破加分 = 最大突破加分 × 突破强度
有效质量 = min(100, 质量分 + 突破加分)
有效半衰期 = 基础半衰期 + 最大延长小时 × 突破强度
热度 = 有效质量 × 0.5 ^ (距发布时间小时数 / 有效半衰期)
```

默认参数：

- 最大突破加分：10；
- 基础半衰期：36 小时；
- 最大延长：18 小时。

不满足技术突破必要条件时强度为 0，公式严格退化为旧公式。热度仍限制在 0 到 100，不改变质量分、精选阈值或可信度含义。

前端单条计算与热点 SQL 排序必须使用同一公式和同一持久化字段，并有等价性测试，防止显示热度与列表排序漂移。

## 11. 界面解释

合格新闻卡片显示克制的“技术突破 +N”标记。展开“五维研判”时补充：

- 技术对象；
- 完成/验证动作；
- 权威或多源证据；
- 突破强度；
- 对热度初值和衰减的影响。

未通过可信门槛的新闻不显示标记。调试性内部规则、正则或完整 JSON 不直接展示给普通用户。

## 12. 数据库与兼容

`articles` 表幂等增加：

- `breakthrough_score REAL NOT NULL DEFAULT 0`
- `breakthrough_bonus REAL NOT NULL DEFAULT 0`
- `breakthrough_signals_json TEXT`
- `scoring_version INTEGER NOT NULL DEFAULT 1`

现有数据库升级不重建、不丢数据。近期相关条目在启动后的聚类重算中补齐新字段；更老条目保持 0，直到被明确重算。归档读取旧条目时以 0 和空信号输出，不制造历史判定。

`daily_reports` 升级窗口版本并保存新的统计和分组，但仍沿用原表与日期唯一键。旧缓存报告在读取时自动重新生成，不要求数据库迁移脚本删除历史行。

## 13. 错误处理

- 目录取消：保持关闭，不显示错误。
- 目录不可写：拒绝启用并说明原因。
- 外接磁盘离线：记录 `directory-unavailable`，不推进成功日期。
- 后端未就绪：短退避重试，超过上限后保留待补齐。
- 日期数据为空：仍生成合法的空简报、空 JSONL 和 manifest。
- 某条 JSON 序列化失败：整个日期失败，不输出缺行却标为成功的清单。
- 磁盘空间不足：保留暂存目录状态并报告，不覆盖旧归档。
- 系统休眠跨过 8 点：恢复后立即执行到期检查。
- 多窗口或重复点击：同一日期共享一个任务，不并发写两份。
- 状态消息不包含 API Key、文章全文或用户目录之外的路径。

## 14. 测试策略

### 每日数据集

- 8:00 开闭区间边界精确；
- 使用 `fetched_at` 纳入迟到新闻；
- JSONL 保留同簇所有报道；
- Markdown 折叠事件簇且保留完整索引；
- 未分析、无摘要、坏 URL 和空日报稳定降级；
- JSONL 字段、排序和 UTF-8 输出确定；
- manifest 数量、字节和 SHA-256 正确。

### 调度与文件系统

- 首次开启选择、取消、不可写目录和更换目录；

## 验收标准

- 用户首次开启自动保存时一定看到原生目录选择窗口，取消不会误开启。
- 应用运行时每天 8:00 自动保存固定前 24 小时窗口。
- 应用未运行或目录暂时不可用时，之后能够补齐且不重复覆盖。
- 每日目录同时包含可读简报、全量 JSONL 和通过校验的 manifest。
- JSONL 覆盖窗口内全部采集记录，而不是只保存精选新闻。
- 归档不包含凭据、搜索词和任意用户私有字段。
- 低空经济与商业航天的可信技术突破在热点中获得明确、有限、可解释的提升。
- 计划、传闻、营销或低可信单点声明不能仅靠关键词获得突破加成。
- 热点 SQL 排序与界面显示公式一致；零突破强度完全兼容旧热度。
- 现有核心功能、数据、设置和自动更新保持可用。
- 本地代码、文档、版本号、安装资产、标签和 GitHub Release 全部为 v0.0.13。
