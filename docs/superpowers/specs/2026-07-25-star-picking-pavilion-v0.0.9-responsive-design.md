# 摘星阁 v0.0.9 全尺寸自适应排版与可靠性复查设计

**状态：** 已确认
**目标版本：** `v0.0.9`
**日期：** 2026-07-25

## 1. 背景与问题

v0.0.8 已完成字体、字号、行距、间距、圆角和栏宽的统一标尺改造，并提供“小 / 标准 / 大 / 特大”四档界面缩放。当前根字号会随窗口宽度连续变化，主要尺寸也已由 `rem` 派生。

真实 Electron 尺寸矩阵审计表明，现有界面没有普遍性的文档级横向滚动，但仍存在两个结构性问题：

1. Electron 最小窗口仍固定为 `1080×680`，用户无法把产品缩小到适合并排办公的尺寸。
2. 顶栏、设置双栏、热点侧栏等布局切换仍依赖固定像素断点。用户选择“大”或“特大”档后，组件本身会变大，断点却不会提前触发。以 `1440×920 + 特大` 为例，顶栏高度可增长到约 222px；以 `1080×680 + 特大` 为例，顶栏与导航合计占据大量首屏空间，正文展示明显受压。

v0.0.9 将把“尺寸同比例变化”升级为“布局按内容能力自适应”：无论窗口缩放还是界面缩放，所有核心入口保持完整可见，组件按实际可用空间自然换行或降栏，不依赖用户发现横向滚动或折叠菜单。

本版本同时复查核心功能与全部启用信源，避免排版升级掩盖功能、网络或发布链路问题。

## 2. 方案比较与决策

### 方案 A：完整自适应堆叠

顶栏、统计区、主导航、筛选器和按钮组按内容自然换行；八个主导航始终同时可见；多栏内容在空间不足时自动变成单栏。该方案操作路径不变，最符合“完整排列并完整呈现”，采用此方案。

### 方案 B：主导航单行横向滚动

纵向占用较少，但窗口较窄时部分主功能移出首屏，依赖用户发现并使用横向滚动，不符合完整呈现要求。

### 方案 C：主导航折叠菜单

最节省空间，但隐藏入口、改变同事既有操作习惯，也扩大了本次纯排版升级的行为范围，不采用。

## 3. 目标、范围与非目标

### 3.1 目标

- Windows 桌面窗口最小支持约 `800×600`。
- 窗口从最小尺寸放大到宽屏时，布局连续、整齐且没有核心内容裁切。
- 四档界面缩放与窗口尺寸组合使用时，布局仍能按内容能力提前换行或降栏。
- 八个主导航入口始终可见，不使用横向滚动或折叠菜单隐藏。
- 深色与浅色主题、全部核心视图和主要浮层均通过尺寸矩阵验证。
- 核心功能、偏好持久化、真实 Electron 生命周期、发布门禁和启用信源完成一次完整复查。

### 3.2 本版本范围

- Electron 窗口最小尺寸。
- 顶栏品牌区、统计区、搜索与快捷操作区。
- 主导航、领域筛选和动态分类筛选。
- 信息流与热点侧栏、卡片、日报、常用网址、信源、设置。
- 表单、按钮组、对话框、词库面板、Toast 与长文本防溢出。
- 响应式布局契约测试与真实 Electron 尺寸矩阵测试。
- 核心功能回归、启用信源实时健康审计和必要的信源配置修复。
- v0.0.9 版本、文档、安装包、标签和 Release 工作流。

### 3.3 非目标

- 不重做 v0.0.8 已确立的深空塔台视觉、双主题和字体体系。
- 不新增业务栏目、采集器类型、AI 模型能力或数据表。
- 不改变 API Key 加密、随机回环端口、保留策略、评分公式或后台运行策略。
- 不以隐藏入口、缩小到不可读字号或裁切文本换取表面上的紧凑。
- 不承诺在低于 `800×600` 的窗口中保持完整桌面体验。

## 4. 响应式布局架构

### 4.1 内容驱动原则

v0.0.9 不再把固定像素断点作为主要布局依据，而使用内在尺寸约束：

- 可换行的功能组使用 `flex-wrap`，并为可压缩内容设置 `min-width: 0`。
- 卡片与表单网格使用 `auto-fit` / `minmax(min(100%, …), 1fr)`，让栏数由容器实际宽度决定。
- 固定栏宽只用于表达舒适阅读宽度，不阻止容器降为单栏。
- 长 URL、模型名、标题和说明文本获得明确的换行或断词策略。
- 弹窗和面板同时限制视口宽度与高度，内容超出时在面板内部滚动。
- 只有纯装饰层允许超出视口；任何可交互元素都不得越界。

根字号和四档缩放继续作为统一尺寸标尺，但布局是否换行由组件实际容纳能力决定，从而消除“字号变大、像素断点不动”的矛盾。

### 4.2 顶栏

顶栏保持三个语义组：品牌、运行统计、搜索与快捷操作。

- 宽屏：三个语义组尽量保持一行。
- 空间不足：统计区成为完整的四列行；品牌与快捷操作保留在上一行。
- 进一步变窄或使用特大缩放：搜索框占据独立整行，实时开关、主题和刷新按钮保持可见并整齐排列。
- 统计标签不从汉字中间断开；品牌副标题允许在极窄状态下受控换行，不撑破窗口。

目标不是强行压缩顶栏高度，而是在每次换行后仍保持明确的品牌、状态与动作层级。

### 4.3 主导航与筛选

- 八个主导航在宽屏保持单行，在窄窗按内容自然分成两行。
- 导航按钮保持稳定顺序、完整文本和足够点击面积。
- 激活指示块继续由现有脚本按按钮实际位置同步，换行后仍准确覆盖当前标签。
- 领域筛选和动态分类筛选作为次级控制组，空间不足时进入独立行。
- 切换到不需要信息流筛选的视图后，隐藏筛选器时不得留下空白占位。
- 粘性导航高度继续由脚本读取真实尺寸并回写，热点侧栏的粘顶偏移始终与当前导航高度一致。

### 4.4 主内容

- 信息流在容器允许时保留“主列表 + 热点侧栏”，容纳不足时自动降为单栏；热点内容不得永久丢失，降栏后以完整的次级区块呈现。
- 设置、信源和常用网址网格按卡片最低可读宽度自动选择栏数。
- 日报头部、导出工具条、信源操作和设置按钮组可换行，主操作顺序不变。
- 信息卡片中的标题、分数、缩略图、星标、复制与维度展开在窄窗中重新排布，不相互遮挡。
- 维护统计和表单双字段在无法容纳时降为单列。

## 5. 视口与缩放验收矩阵

自动化至少覆盖以下桌面窗口：

- `800×600`
- `1080×680`
- `1440×920`
- `1920×1080`

每个窗口覆盖 `sm / md / lg / xl` 四档缩放，并至少抽查深色与浅色主题。核心视图包括：

- 精选信息流
- 情报日报
- 常用网址
- 信源
- 设置

每个组合验证：

- `documentElement.scrollWidth` 不大于可视宽度。
- 除明确允许越界的装饰层外，可见交互元素的边界均在视口内。
- 主导航八个入口可见且可点击。
- 当前视图标题、主操作和首个内容区块可达。
- 粘性导航与浮层不会覆盖不可恢复的核心内容。
- 界面缩放切换后导航高度和激活指示块完成同步。

## 6. 核心功能复查

真实 Electron 冒烟测试覆盖：

- 主导航与视图切换。
- 全文搜索、清除搜索、领域筛选和动态分类筛选。
- 深浅主题、四档缩放和偏好跨重启恢复。
- 实时更新开关与立即采集。
- 信息卡片展开、事件簇、星标、复制和 Markdown 导出。
- 日报日期切换、重新生成、复制和导出。
- 常用网址分类、星标与安全外链。
- 信源新增、启停、强制重试、删除保护和健康状态。
- AI 设置保存、加密凭据确认与连接测试。
- 采集间隔、RSSHub、情报备忘、数据维护和桌面运行设置。
- 单实例唤醒、后台隐藏、再次启动、重启恢复和优雅退出。

排版修改不得削弱 CSP、外链拦截、preload 权限边界、凭据加密、HTTP 安全或输入校验。

## 7. 信源实时健康审计

对 `config/sources.default.json` 中全部启用信源执行真实网络检查：

1. 通过产品现有采集器和超时策略逐个请求。
2. 校验 HTTP 状态、响应类型、解析结果和最少有效条目。
3. 对超时、限流和临时服务错误执行一次受控重试。
4. 将失败区分为网络瞬时错误、上游反爬 / 限流、解析规则失效、地址迁移和永久下线。
5. 对可确认的配置失效进行最小修复；不因单次网络波动删除信源。
6. 修复后重新运行目标信源与完整健康检查。

实时审计结果必须报告总数、正常数、受限数、失败数与修复项。若某个外部站点在发布时仍受限，界面必须将其标为可理解的退避状态，且不得拖垮其他信源采集。

## 8. 错误处理与降级

- 布局测试发现越界时，报告具体窗口、缩放、视图和元素，不以提高 Electron 最小尺寸规避。
- 热点区无法与主列表并排时降为下方完整区块，不直接隐藏。
- 长文本优先换行；只有不影响识别的次要单行名称可使用省略号，并保留完整 `title` 或可访问名称。
- 浮层高度不足时内部滚动，关闭按钮始终留在可视范围。
- 信源瞬时失败沿用退避机制；配置失败提供明确状态并允许强制重试。
- 网络不可用时，现有本地数据库、星标、日报、备忘和设置仍可使用。
- 功能复查发现的缺陷必须先添加回归测试再修复。

## 9. 测试策略

严格采用测试先行。

### 9.1 响应式契约测试

先增加失败测试，约束：

- Electron 最小窗口为约 `800×600`。
- 主要网格使用内容驱动的自动降栏规则。
- 顶栏、导航、筛选、日报动作和按钮组允许受控换行。
- 热点区在窄容器中仍有可见的降栏形态。
- 长内容和浮层具备防溢出规则。
- 新增样式不重新引入写死像素字号、行高或字距。

### 9.2 真实 Electron 尺寸矩阵

使用 Playwright 启动真实 Electron，在隔离测试数据目录中循环窗口、缩放、主题和核心视图，检查文档宽度、交互元素边界、主导航可见性和关键操作。

测试必须能在 v0.0.8 现状上因最小窗口或布局缺陷明确失败，并在实现后通过。

### 9.3 既有回归

- `npm test`
- `npm run test:e2e`
- `npm run audit:runtime`
- `npm run notices`
- `git diff --exit-code -- THIRD_PARTY_NOTICES.txt`
- `npm run dist`
- `npm run verify:package`
- `npm run verify:version -- --tag v0.0.9 --artifacts`

同时执行启用信源实时健康审计，并记录无法由本地单元测试替代的外部状态。

## 11. 验收标准

- 用户可把窗口缩小到约 `800×600`，所有核心入口仍完整可见、可操作。
- 在验收矩阵中不存在文档级横向滚动、交互元素越界或核心内容不可恢复地被遮挡。
- 四档缩放与窗口大小组合变化时，顶栏、导航、筛选和内容网格按内容自动重排。
- 八个主导航不折叠、不横向滚动、不缩写。
- 热点、设置、信源、网址、日报和弹窗在空间不足时以完整单栏或内部滚动呈现。
- 全部自动化测试、真实 Electron E2E、生产依赖审计、构建与包校验通过。
- 启用信源完成实时审计；可确认的失效配置已修复并复测，瞬时受限状态被如实记录。
- v0.0.9 版本元数据、文档、提交、标签和远端发布状态一致。
